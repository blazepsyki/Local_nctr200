## 1. 실행 환경과 범위

Windows Python 3.13.15에서 자동 시험과 기존 PCAP 분석을 실행했습니다. 로컬 WSL에는 배포판이 없었으며 Ubuntu·실물 보일러·실제 DNS 서버에 새 코드로 접속하지 않았습니다. 모든 자동 네트워크 시험은 합성 자료와 loopback을 사용했습니다.

서버·분석 도구는 Python 3.10 이상의 표준 라이브러리를 사용합니다. Ubuntu 호환성은 배포 후 동일 시험·사전 점검으로 확인해야 하며 이번 결과를 Ubuntu 통과로 해석하지 않습니다. TShark 4.6.9는 PCAP 추출에만 사용했습니다.

## 2. 자동 시험

```powershell
python -m unittest discover -s tests -v
python src/nctr_lab_cli.py doctor --bind 127.0.0.1 --port 0
```

자동 시험 52개가 통과했습니다. 실제 테스트 목록은 [test_lab.py](../tests/test_lab.py)에 있습니다. 배포 ZIP의 임시 압축 해제본에서도 같은 52개 시험과 배포 파일 해시 검사를 수행했습니다. 실행 로그는 작업 폴더 시험과 배포본 시험에 보관합니다.

| 범위 | 검사한 동작 |
|---|---|
| 프레임 | 매 분할 경계·병합·큰 body·미완성·잘못된 길이·정상 프레임 뒤 오류 |
| 초기·프로파일 | 식별·순서·ID 불일치, 알려진 ID bootstrap, `0001` 길이 정책, `01FF` 변형·준비 상태 |
| 명령 | 활성화·범위·확인·신선도 차단, body 있는 이벤트와 ACK 분리, ACK와 실제 반영 분리 |
| 수명주기 | 단일 pending, 재접속, 기한·취소, 늦은 ACK, 토큰 미재사용, 자동 재전송 없음 |
| 수집·저장 | 전문·미해독, 회전·예산·디스크 오류, 동시 순번·무결성·기존 실행 덮어쓰기 금지 |
| 소켓 | 실제 loopback 접속·분할 전송, 중복 접속 거부, 파싱·기록 실패 시 종료 |
| 분석·공유 | 소켓 생성 없는 재생, 차분, 원본과 프레임 비교, 공유 메타데이터에 ID·body·IP·marker 제외 |
| PCAP | 순서 역전·재전송·seq wrap·gap·충돌, 방향별 초기 길이 예외, 캡처 시각 기반 ACK 대응 |
| DNS | 합성 UDP 질의·압축 응답, 잘못된 ID·잘린 응답, DNS 점검과 장치 경로 증명 구분 |
| 배포·첨부 | ZIP에 raw·PCAP·ADB 제외, 파일 해시, 변조 탐지, 첨부 해시·덮어쓰기 금지 |

전체 실험 계획의 T01~T20을 모두 완료했다는 뜻은 아닙니다. 예약·보안 페어링·HA, 모든 기능 인코더, 장시간 실물 운전은 아직 후속 개발·시험입니다.

## 3. 기존 PCAP 3개의 오프라인 재검증

TShark는 이름 조회를 끈 `-n`으로 실행했습니다. 실제 TCP seq를 재조립하고 재전송을 중복 제거한 뒤, 방향별 프레임과 RX raw 재생을 비교했습니다. 원본 PCAP의 내용은 변경하지 않았습니다.

| 원본 | 추출한 TCP payload 패킷 | gap·충돌·파싱 경고 | RX 재생과 로그 | 서버 기능 명령과 ACK 대응 |
|---|---:|---:|---|---|
| `261015_packet_boiler.pcapng` | 21 | 0 | 일치 | 4건 중 4건 |
| `261017_packet_bolier.pcapng` | 30 | 0 | 일치 | 10건 중 9건 |
| `261017_packet_bolier2.pcapng` | 12 | 0 | 일치 | 1건 중 1건 |

명령 건수는 서버발 `0100` 이상·body 있는 프레임과 같은 세션·ID·token의 빈 RX ACK를 분석한 결과입니다. `0002` 등 초기 교환은 이 수에 포함하지 않았습니다. ACK를 대응하지 못한 1건은 캡처 구간에서 미확인한 것으로, 명령 미적용을 입증하지 않습니다.

10월 15일 자료의 두 `01FF` 사이에는 body offset 0·10·90의 세 차분이 다시 관측됐습니다. 해당 바이트 의미는 이 결과만으로 확정하지 않습니다. 10월 17일 첫 자료에서 `0105`·`0115` RX도 관측됐으며, 메시지 관측과 로컬 명령 적용 검증은 구분합니다.

결과 위치는 다음과 같습니다. 파일들은 로컬 비공개 원본을 포함하므로 외부 공유용 자료로 취급하지 않습니다.

- 10월 15일 분석 요약
- 10월 17일 첫 분석 요약
- 10월 17일 둘째 분석 요약

## 4. 남은 현장 검증

1. Windows 배포 ZIP과 Ubuntu 전송본의 SHA-256, 해제 후 `check-bundle`을 확인합니다.
2. Ubuntu에서 같은 자동 시험과 `doctor`를 수행합니다. Python 버전·IP·포트·DNS·여유 공간을 기록합니다.
3. 실제 조절기 DNS 응답과 TCP 접속원을 확인합니다. NAT peer를 장치 IP로 단정하지 않습니다.
4. 제어를 켜지 않은 새 수집 회차에서 `0001`·정상 상태·물리 조작·모든 이벤트를 기록합니다.
5. 종료·복구·해시·PCAP drop을 확인하고 자료를 회수합니다. 그 결과로 온도·전원 및 후속 기능의 실물 시험을 진행합니다.

새 도구의 실물 연결 성공, 모든 메시지 의미, 완전 오프라인 동작, 보안 페어링이나 운영 안정성은 아직 확인한 결과가 아닙니다.
