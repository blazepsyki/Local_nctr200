## 1. 목표와 개정 방향

**충분한 원본 자료를 확보하고 기능별로 검증하는 것을 목표로 삼습니다. 필요한 수집기·프로토콜 처리·명령 기능을 개발하면서 실험 범위를 넓힙니다.** v4는 기존 성공 경로와 결함을 확인하는 참고 구현입니다. 온도 범위, ACK 대상, 로그 형식, 모드 이름, 파일 구조를 새 구현의 고정 요구사항으로 삼지 않습니다.

개발 순서는 원본·사건 수집 → 프레임·세션 처리 보완 → 오프라인 분석 → 정상 기능 탐색 → 기능별 명령 구현·실물 비교입니다. 난방·외출 외에도 전원, 온돌, 온수, 목욕, 예약, 등록 코드, 연결 복구, 제조사 의존성과 HA 노출까지 조사합니다. 모든 기능을 한 번에 자동 제어하는 시험으로 시작하지는 않습니다.

| 항목 | 1판 | 이번 계획 |
|---|---|---|
| 구현 기준 | v4의 관찰·온도 명령 중심 | 수집·분석·명령 계층을 보완하거나 분리 |
| 수집 | 주로 `0102`·`0106`·103바이트 `01FF` | 모든 RX/TX 원본, 미해독·비정상 데이터, 연결·명령·조작 이력, 관측 가능한 DNS·HTTP·앱 로그 |
| 기능 | 실내온도·외출·단일 원격 온도 | 기능별 지원 여부, 모드·상태·명령, 예약·등록·복구·오프라인 조건 |
| 완료 판단 | 일부 필드 대응 | 기능·경로별 근거, 미해결·미지원, 수집 누락과 복구 결과 |

확인 사실은 기존 기록 또는 새 원본 자료로 뒷받침된 내용으로 제한합니다. APK에 있는 ID·필드·기능명은 실제 단독 조절기의 지원을 보장하지 않습니다. 원격 명령과 장치발 보고가 같은 ID를 쓰더라도 의미·방향·body가 같다고 가정하지 않습니다. 계획 확대는 새 기능의 검증 완료를 뜻하지 않습니다.

## 2. 수집 범위와 저장 설계

### 2.1 계층별 자료

| 계층 | 반드시 남길 내용 | 위치·한계 |
|---|---|---|
| 네트워크 | TCP SYN/FIN/RST·재전송·payload, 관측 가능한 DNS·HTTP·DHCP | TCP는 로컬 서버, 나머지는 실제 경로상의 AP·라우터·DNS 서버 등에서 수집 |
| 소켓 원본 | `recv()` 청크 전문, TX 요청 바이트·완료·실패, 세션 내 바이트 offset | 파싱 전 비공개 원본 저장. 청크 경계를 프레임 경계로 취급하지 않음 |
| 응용 프레임 | 방향, ID, 토큰, 선언·실제 길이, 전체 body, 원본 참조 | 알려진 ID·body 길이만 저장하는 필터 제거. 미해독·파싱 실패·잔여 버퍼도 보존 |
| 세션 | 접속·종료·재접속·peer, 준비 상태 전이, 코드·설정·ACK 정책 버전 | 실행·세션 ID를 실제 장치 ID와 분리 |
| 명령 | 요청자·기능·값, 인코딩, TX 시도·완료·실패, ACK, 상태 반영·시간 초과·취소 | `command_id`와 token 구분. 전송 완료가 장치 수신을 증명하지 않음 |
| 물리 관찰 | 조작 전후 LCD·모드·표시, 시각, 사진·영상, 다른 조작 유무 | 현장 사용자가 기록. 로그로 LCD 관측값을 대신 채우지 않음 |
| 앱·서버 선택 | 공식 앱 조작, 가능한 Logcat, DNS 질의·응답, HTTP 요청·응답 | 본인 기기·계정의 정상 사용만 수집. HTTPS body는 TCP 캡처만으로 읽을 수 없음 |
| 수집 상태 | 기록 큐·누락 수, 쓰기 오류·디스크, PCAP drop 통계, 구간·파일 해시 | 자료가 누락된 구간을 성공 근거로 사용하지 않음 |

큰 body와 미지원 ID를 생략하지 않습니다. 정상·중복·오류 데이터를 원본에 남기고 보기와 해석 단계에서만 필터링합니다. 비정상 길이 때문에 연결을 닫더라도 원본·버퍼·종료 사유를 남깁니다. 미해독 데이터를 실제 상태에 반영하거나 일괄 ACK하지 않습니다.

### 2.2 사건과 시간

모든 사건에 `schema_version`, `run_id`, `session_id`, `event_seq`, `event_type`, KST 절대시각, 프로세스 단조 증가 시각을 둡니다. 프레임에는 방향·ID·token·길이·원본 offset, 명령에는 `command_id`, 사용자 조작에는 `action_id`를 연결합니다. 연결 전 DNS 등에는 세션 ID 없이 실행 ID와 장치 별칭을 사용할 수 있습니다.

PC·휴대전화·캡처 장비 사이 시간 차이와 오차를 기록합니다. 단조 증가 시각은 같은 프로세스의 경과 시간에만 사용합니다. 사진 시간 오차 안에 여러 조작이 있으면 인과관계를 미판정으로 남깁니다. 중복 이벤트를 상태 처리에서 제외해도 원본은 지우지 않습니다.

### 2.3 실행별 자료 묶음

새 자료는 `experiments/<run_id>/`에 모읍니다. 아래는 개발할 저장 구조이며 아직 생성 도구는 없습니다. 파일명·식별자는 영문, 사람이 쓰는 문서는 한국어로 작성합니다.

| 파일·디렉터리 | 내용 |
|---|---|
| `manifest.json` | 코드·설정·정책·스키마 버전, 경로·모드·관측 위치, 시간 차이, 시작·종료, 파일 해시 |
| `environment.txt` | Python·OS·시간대, 필요한 IP·네트워크·DNS·방화벽 정보 |
| `raw/` | 소켓 청크·TX 원본과 인덱스. 전체 식별자를 포함할 수 있는 비공개 자료 |
| `network/` | 관측 위치별 PCAP·통계·DNS 로그 |
| `events.jsonl`, `commands.jsonl` | 프레임·세션·수집 상태, 명령 생명주기 |
| `observations.md`, `media/` | 조작·LCD 기록, 사진·영상 |
| `analysis/` | 시계열, offset·비트 차분, 지연, 미해독 ID·길이 목록 |
| `coverage.csv`, `result.md` | 기능·경로별 검증 수준·판정·근거·복구 |
| `export/` | 식별자·자격증명·관계없는 통신을 제거한 공유용 사본 |

로컬 원본은 가능한 전문을 보존하고 공유용 사본에서 마스킹합니다. 프로비저닝·앱 로그의 암호·토큰을 다른 로그에 불필요하게 복제하지 않습니다. 원본 접근을 제한하고 운영체제에 맞는 권한 처리를 사용합니다. Windows에 POSIX 권한 호출을 그대로 적용하지 않습니다.

파일은 크기·시간 기준으로 분할하고 순번·구간·해시를 보존합니다. 활성 실행 중 이전 구간을 자동 삭제하는 순환 버퍼를 기본으로 삼지 않습니다. 먼저 저장 증가량을 측정하고 공간을 예약합니다. 디스크·큐 부족 시 새 제어를 차단하고 오류·누락 수·최종 저장 구간을 남깁니다. 수집 기능이 세션 처리까지 무한정 막거나 메모리를 무제한 사용하는 경우도 모의 시험합니다.

구체적인 기존 한계는 다음처럼 수정합니다.

- **고정 온도 범위:** 18~30°C는 과거 실험 제한입니다. 실내·온돌·온수의 실제 지원 범위와 단위를 조사해 각각 검증합니다. 범위 확대가 극단값의 실물 자동 전송을 뜻하지 않습니다.
- **상태 길이:** 103바이트는 확인된 프로파일입니다. 다른 길이도 원본에 저장하고 변형을 조사하되 해석·제어 준비 근거로 즉시 사용하지 않습니다.
- **ACK·pending:** 같은 ID·token이라는 이유로 body 있는 이벤트를 ACK로 소비하지 않습니다. 미지원 ID도 정상 응답 규칙을 확보하면 지원을 추가할 수 있습니다.
- **신선도:** 기능별 필수 보고와 실제 주기에 맞춰 제어 준비 조건을 정의합니다. 단순히 살아 있는 소켓이나 과거 `ready=True`를 근거로 삼지 않습니다.
- **식별자:** `0000` 선행 세션은 본인 자료의 전체 ID로 대응하도록 지원합니다. 4바이트 요청으로 나머지 ID를 만들지 않으며 원본과 공유본을 구분합니다.
- **초기 시간 응답:** 미해독 2바이트·길이 예외는 날짜·시각별 정상 자료와 비교하는 실험 변수입니다. `0123`을 고정 정답으로 삼지 않습니다.

## 4. 수집·비교 경로

| 경로 | 수행 방법 | 얻을 근거 |
|---|---|---|
| A 제조사 정상 경로 | 공식 앱·조절기로 본인 기기를 조작하고 경로상에서 장치 TCP·가능한 DNS/HTTP·앱 로그 수집 | 정상 명령·ACK·보고·LCD 대응 |
| B 로컬·물리 조작 | 확인된 DNS 우회 등에 수집 서버 사용. 기능 명령을 끄고 조절기를 조작 | 로컬 응답 정책에서 이벤트·스냅샷과 A의 차이 |
| C 로컬·원격 명령 | A/B로 근거가 생긴 기능의 인코더를 구현해 하나씩 전송 | TX·ACK·실물 적용·보고와 A/B 비교 |
| D 연결·의존성 | 서버 재시작·시험 장치 연결 복구·DNS/HTTP 조건을 한 번에 하나씩 변경 | 실패 단계, 재시도·복구 지연, 초기 교환 |
| O 오프라인·모의 | 기존·신규 자료 재생과 오류 입력 | 파싱·상태·명령·기록·정책 회귀 |

기존 캡처를 먼저 분석해 불필요한 재등록·초기화를 줄입니다. A에서 필요한 계정 등록 상태와 A↔B 전환의 DNS·연결·계정 변경을 기록합니다. 전환 전후를 같은 세션으로 비교하지 않습니다. A를 볼 수 있는 캡처 지점이 없다면 결손을 표시하고 B의 정상 물리 조작부터 수집합니다.

로컬 서버의 NAT peer IP와 AP의 실제 장치 IP·MAC을 구분합니다. 서버에서는 주로 TCP가 보이며 DNS·HTTP·DHCP까지 얻는다고 가정하지 않습니다. 다음은 기존 `tcpdump`를 사용하는 Ubuntu Bash 예시입니다. 실측 변수·출력 디렉터리를 먼저 준비하고 캡처 위치를 manifest에 기록합니다.

```bash
sudo tcpdump -i "$NCTR_CAPTURE_IFACE" -s 0 -U \
  -w "$RUN_DIR/network/server_tcp.pcap" \
  "host $NCTR_PEER_IP and tcp port 20000"
```

AP·라우터 등 실제 장치 트래픽을 볼 수 있는 위치에서는 실제 장치 IP를 사용해 프로토콜 제한 없이 수집할 수 있습니다. 이 필터도 DHCP broadcast는 빠질 수 있으므로 DHCP 임대 로그나 장치 MAC을 식별할 수 있는 위치의 별도 캡처로 보완합니다. 다른 가정용 기기 전체 통신을 무조건 모으는 필터로 확대하지 않습니다.

```bash
sudo tcpdump -i "$NCTR_CAPTURE_IFACE" -s 0 -U \
  -w "$RUN_DIR/network/device_path.pcap" \
  "host $NCTR_DEVICE_IP"
```

앱 로그는 실제 출력 범위만 확보할 수 있습니다. 읽지 못한 HTTPS body를 확보했다고 표시하지 않습니다. 새 수집기의 CLI는 구현 후 도움말·설정 예시·실행 절차를 추가합니다. 아직 없는 옵션을 실행 예시로 제시하지 않습니다. ACK·초기 응답을 송신하는 로컬 모드는 완전 수동 캡처와 구분합니다.

## 5. 기능별 검증 표

ID 연결은 과거 APK 보고서와 인수인계의 후보입니다. 해당 단독 조절기의 실제 지원과 TCP 방향을 다시 확인합니다. 기능별로 A 정상 경로 → B 물리 관찰 → 인코더 구현 → C 원격 비교를 진행하고 제공되지 않는 경로는 `해당 없음`으로 기록합니다.

| E01 | 초기·전체 상태 `0000/0001/01FF` | 최초·반복 연결, body 변형, 주기·초기 응답 | 초기 정책별 세션 유지·복구 |

미관측 ID는 발생 상황·방향·길이·body·응답과 함께 별도 등록합니다. 실제 UI가 없거나 지원이 불명확한 기능을 무작위 패킷 전송으로 찾지 않습니다. 오류를 얻기 위해 센서·배선·연소·급수 계통에 장애를 만들지 않습니다.

## 6. 단계별 절차

### 6.1 수집기 개발과 기존 자료 분석

1. 보유 PCAP 5개·Android 로그·코드의 해시, 시점, 관측 지점·민감 정보 여부를 목록화합니다.
2. TCP를 방향별로 재조립해 모든 ID·길이·token·지연·초기 응답을 추출합니다. APK 보고서와 비교하되 Java 원본이 현재 없는 한계를 표시합니다.
3. D01~D05를 구현하고 T01~T16을 수행합니다. 제어 전에 원본 저장, 세션·ACK 구분, 명령 차단·상관관계·오류 기록을 통과해야 합니다.
4. 재생 결과를 원문과 대조합니다. v4와 새 구현의 초기 응답·ACK 차이를 열거하고 근거를 남깁니다.

### 6.2 정상 기능을 넓게 수집

1. A/B에서 무조작 기준선을 확보합니다. 목표는 연속 보고 3개와 LCD입니다. 수집 경로가 유효하다면 일부 보고가 부족해도 다른 정상 기능의 관찰은 가능하고, 스냅샷 판정만 보류합니다.
2. 실제 UI가 제공하는 기능을 목록화하고 E02·E03·E06~E10을 작은 회차로 나눕니다. 한 회차에서 온도·모드·전원·예약을 동시에 바꾸지 않습니다.
3. 조작마다 `action_id`, 전후 값·모드·사진·시각, 관련 모든 이벤트·전후 스냅샷을 남깁니다. 제조사와 로컬 서버의 응답 차이도 기록합니다.
4. 첫 회차에서는 기능·후보 필드를 넓게 찾습니다. 다음 회차에서는 원래 값→변경값→원래 값의 왕복을 최소 2회 확인합니다. 안정되면 다른 값·시각·세션 자료를 추가합니다.
5. 일상 장기 기록은 먼저 1시간으로 저장량·누락·연결 안정성을 측정하고, 조건에 맞으면 6시간·24시간으로 늘립니다. 장시간 기록 자체가 자동 제어를 활성화하지는 않습니다.

### 6.3 기능별 명령 구현과 비교

1. 해당 기능의 정상 패킷·방향·값·복구 방법을 확보하고 D06에 인코더를 추가합니다. 단위·범위·선행 모드·출처·검증 수준을 기능별로 관리합니다.
2. 인코딩·범위·길이·부작용·취소를 먼저 모의 시험합니다. 모르는 필드의 모든 조합을 실물에 전송하지 않습니다.
3. 현재 세션의 유효·최근 상태와 LCD를 확인합니다. 신선도는 기능·보고 주기에 맞추고 임의로 짧은 시간을 적용해 정상 장치의 모든 명령을 차단하지 않도록 시험합니다.
4. 한 번의 명시적 명령을 보내고 요청·ACK·LCD·장치 보고를 비교합니다. `ownerState` 등 body 차이는 정상 자료에 근거한 후보 하나만 별도 회차에서 변경합니다.
5. 단일 기능이 확인되면 실내↔온돌, 외출 전후 목표 보존, 전원 복귀, 온수 전용과 난방 복귀 등 정상 UI의 조합을 추가합니다. 선행 모드를 항상 기록합니다.
6. 실패해 보여도 자동 반복 전송하지 않습니다. 수집 누락·결과를 확인하고, 재시도는 새 `command_id`와 출처·횟수로 기록합니다.

### 6.4 기능별 특별 절차

- **E02·E04:** 목표는 1단위 왕복으로 시작합니다. 현재온도는 자연 변화·LCD를 대조하고 변화가 없으면 미판정입니다. body offset 16·32의 과거 값만으로 의미를 고정하지 않습니다.
- **E03·E06:** 외출과 소프트웨어 전원을 따로 시험합니다. OFF에서 TCP 유지·재접속 여부와 ON 복귀 후 목표·모드 보존을 확인합니다.
- **E07~E09:** 실내·난방수·생활온수의 단위·범위를 분리합니다. 설정 반영과 실제 가열·출수 성능을 별도 판정합니다.
- **E10:** 기존 예약을 백업하고 관찰 가능한 시각에 단일 짧은 예약을 생성합니다. 시작·종료·취소·다음 예약 없음·원래 설정 복구까지 확인합니다. 인터넷 조건은 형식·동작 확인 후 별도 회차에서 바꿉니다.
- **E11:** 먼저 코드와 LCD의 대응을 수집합니다. 이후 난수·만료·재발급·단일 사용·시도 제한을 구현합니다. 경계·대량 실패 입력은 모의 시험, 실물은 정상 등록·취소를 확인합니다. 코드 발급과 사용자 제어 권한은 별도 상태입니다.
- **E13:** 서버만 재시작하는 시험부터 시작합니다. 이후 시험 장치의 연결만 끊었다가 복구하는 회차를 둡니다. 명령 중간 단절·ACK 유실은 먼저 모의 시험합니다.
- **E14:** DNS, 제조사 HTTP 접근, 직접 서버 설정을 각각 독립 변수로 삼습니다. 정상 프로비저닝의 데이터그램·응답·저장·재시작을 확보하고 백업·복구 후 설정을 바꿉니다. `AT+ABCD` 의미를 추정해 쓰지 않습니다. 오프라인은 기존 연결 유지, 새 TCP 연결, Wi-Fi 재접속·지원되는 사용자 재시작을 구분합니다.
- **E15:** 모니터링·이용 불가부터 연결한 뒤 검증된 단일 제어와 예약·모드로 확장합니다. ACK만 왔거나 연결이 끊겼는데 HA가 성공·최신으로 표시하지 않는지 확인합니다.

### 6.5 관찰 시간과 명령 결과

초기 운영값은 연결 준비 120초, 조작 직후 집중 관찰 60초, 후속 상태 보고 12분입니다. 과거 약 301초 간격을 참고한 값이며 프로토콜 보장이 아닙니다. 수집 후 기능·모드별로 조정하고, 장시간 수집은 별도 실행으로 둡니다. 관찰 기한 이후 자료도 남기되 판정 시점을 구분합니다.

| 관측 | 판정 |
|---|---|
| TX 실패 | 전송 실패. 일부 바이트 송신은 raw·PCAP으로 별도 확인 |
| TX 완료·ACK만 확인 | 수신 확인, 적용 미확인 |
| LCD 변경·이전 값 보고 | 실물 반영 관측·보고 불일치 |
| 검증된 보고가 요청값과 일치 | 보고 반영 확인, LCD 확인 여부 별도 기록 |
| LCD·검증된 보고 모두 일치 | 해당 모드·값·경로에서 적용과 보고 일치 |
| 기한 내 근거 없음 | 확인 시간 초과, 미적용 입증과 구분 |
| 누락·다른 조작·새 세션 | 인과관계 미판정, 확보 자료 보존 |

## 7. 모의·회귀 시험

테스트 하네스는 아직 없습니다. `unittest`, 모의 시계, `socket.socketpair()` 또는 loopback 임시 포트를 사용할 수 있습니다. 합성 ID·토큰을 사용하며 실물로 라우팅하지 않습니다. 표는 목표 요구사항이고 현재 코드의 통과 결과가 아닙니다.

| ID | 대상 | 통과 기준 |
|---|---|---|
| T01 | 분할·병합·반쪽 헤더·body | 모든 바이트 경계에서 손실·중복 없이 재조립 |
| T02 | 잘못된 길이·큰 body·EOF·잡음 | 원본·잔여 저장, 버퍼 상한, 제어 차단·명시적 오류 |
| T03 | 초기 순서·ID 일치·불일치 | 잘못된 학습 방지, `0000`·`0001` 경로별 상태 |
| T04 | `01FF` 길이 변형 | 정상 프로파일만 준비 근거, 다른 길이도 수집 |
| T05 | 인가·모드·범위·취소 | 부적합 TX 0회, 정상 명시적 요청만 1회 |
| T06 | ACK·body 이벤트·토큰 충돌 | ACK 매칭과 이벤트 처리 독립 |
| T07 | 재접속·늦은 ACK·새 세션 | 이전 pending·오래된 상태로 새 명령 완료하지 않음 |
| T08 | 전체 ID·길이·방향·차분 | 미해독 포함 수집, offset·원본 참조 일치 |
| T09 | 실기 자료 재생 | 실행 메타데이터 외 결과 재현, 소켓 송신 없음 |
| T10 | 명령 상태 | TX·ACK·보고·LCD·시간 초과·취소 구분 |
| T11 | 파일·큐·디스크 오류 | 누락 수·마지막 저장 구간 표시, 제어 차단, 메모리 무한 증가 없음 |
| T12 | 분할 저장·종료·재시작 | 구간·해시·flush·손실 여부 확인 |
| T13 | 시간·시간대·시계 보정 | KST·단조 순서, 시계 역행에도 타임아웃 오판 없음 |
| T14 | raw·공유 추출 | 원본 보존, 공유본·오류·bootstrap TX의 식별자 마스킹 |
| T15 | 미해독·ACK 정책 | 수집 유지, 정책 밖 자동 응답 없음, 정책 버전 기록 |
| T16 | v4·새 구현 초기 교환 | TX 차이 열거, 근거 없는 길이·후행 바이트 변경 없음 |
| T17 | 기능별 인코더 | 정상 자료와 일치, 잘못된 단위·모드·값 거부 |
| T18 | 예약·등록 정책 | 슬롯·시각 경계·취소·만료·재사용·시도 제한을 모의 시계로 검증 |
| T19 | 중복·지연·단절·재시도 | 중복 적용 없음, 기본 자동 재전송 없음, 재시도 이력 |
| T20 | HA 상태·이용 불가 | 미확정은 unknown, 오래된 상태·ACK만으로 성공 표시하지 않음 |

기능마다 정상 입력·모드 전환·잘못된 입력·원상복구·보고 불일치 사례를 추가합니다. 지원 범위 전체의 입력 검사는 모의 시험으로 하고, 실물은 근거 있는 대표값과 정상 UI 조작으로 검증합니다. 합성 오류·다중 방·미해독 기능은 실물 통과 건수에 포함하지 않습니다.

## 8. 분석·커버리지·완료 기준

원본에서 방향별 TCP 스트림을 재조립하고 사건을 연결합니다. TCP 재전송을 응용 명령 추가 전송으로 세지 않습니다. 같은 세션·프로파일의 차분을 기본으로 하고, 세션 간 비교에는 모드·초기 상태·시각·코드 정책을 표시합니다.

전체 ID·길이·빈도, offset·비트 차분, 무조작 변동, 조작 연관, TX→ACK→보고 지연, 재접속 시간, 누락 구간을 출력합니다. 자동 상관 분석은 후보 탐색에 쓰고 한 번의 동시 변화로 필드 의미를 확정하지 않습니다.

| 검증 수준 | 최소 근거 |
|---|---|
| 미관측 | 후보 출처와 시험하지 못한 이유 |
| 관측 | 정상 UI 또는 프레임 원본·방향·모드·시각 |
| 대응 후보 | 조작 전후 LCD·이벤트·가능한 스냅샷의 연관 |
| 상태 검증 | 최소 2회 왕복과 독립 세션 재확인, 적용 방향·모드 명시 |
| 명령 검증 | 모의 인코더 통과, TX·ACK 여부·LCD·검증된 보고·복구 |
| 조건부·미판정 | 성립 조건·모순·누락·다음 시험 |
| 미지원·해당 없음 | 해당 기기·UI의 확인 경로. 무응답만으로 미지원 판정하지 않음 |

현재온도처럼 왕복이 불가능한 값은 서로 다른 자연 관측값·독립 세션으로 근거를 제시합니다. 소수 표본의 지연을 일반적인 시간 보장으로 표현하지 않습니다. 자료량은 파일 크기보다 기능·경로·모드·값·세션 커버리지로 평가합니다. 같은 상태의 반복 로그만 늘리지 않고 미관측 기능·다른 경로·복구 조건을 채웁니다.

## 9. 실행 전 점검·중단·복구

1. 코드·정책·설정 해시, 실제 IP·관측 위치·시간 차이, 계정 상태, 기존 DNS·예약·LCD 목표·모드와 복구법을 기록합니다.
2. 저장·시각·수집 경로를 확인하고 원본 저장부터 시작합니다. 같은 기기를 조작하는 앱·HA·사용자·서버는 출처·시각을 기록하고 계획 밖의 동시 조작을 피합니다.
3. 잘못된 장치, 예상하지 못한 운전·오류, 기록 손실, 반복 단절, 상태를 알 수 없는 응답에서는 새 명령을 중단합니다. 미해독은 보존하고 실물 무작위 오류 입력은 하지 않습니다.
4. 필요하면 물리 조절기로 즉시 목표·모드를 복구하고 시험 예약을 취소합니다. 복구 이후 사건을 원래 명령 반응에 섞지 않습니다.
5. 종료 flush·PCAP 종료·해시·누락 통계를 기록합니다. 로컬 경로가 불명확하면 백업한 정상 DNS·공식 프로비저닝 경로로 복구합니다.
6. 장애 시험은 시험 장치·서버의 연결에 한정합니다. 가정 전체 네트워크·전원선·배선·센서·연소 보호회로는 변수로 삼지 않습니다. 정상 사용자 조작을 벗어나는 물리 개조는 범위 밖입니다.
