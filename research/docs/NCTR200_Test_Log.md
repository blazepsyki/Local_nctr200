# NCTR-200 시험 기록

작성일: 2026-11-22(KST)  
범위: 2026-10-15 ~ 2026-11-22의 실물 시험과 패킷 캡처  
대상: 귀뚜라미 L20-15HFN 보일러에 연결된 실내 조절기 NCTR-200 WiFi 한 대

이 문서는 공개 저장소에 그대로 옮길 수 있게 썼습니다. 조절기 노드 ID, MAC, 집 안 IP 주소는 넣지 않았습니다. 주소 대신 "NAS", "핫스팟" 같은 역할 이름을 씁니다. 제조사 서버 주소(`121.141.70.70`)는 공개된 값이라 그대로 적었습니다.

## 1. 시험 구성

```text
조절기 ── Wi-Fi 2.4GHz ──> Windows 모바일 핫스팟 (Wireshark 캡처)
                              │ NAT
                              v
                          NAS의 수집 서버 (TCP/20000)
```

- 조절기는 원래 제조사 서버에 TCP/20000으로 접속합니다. 시험에서는 이 접속을 NAS의 수집 서버로 돌렸습니다.
- 돌리는 방법은 두 가지를 썼습니다.
  - 11-21~22 새벽: 로컬 DNS로 `igs4.krb.co.kr`만 NAS 주소로 응답(DNS 우회)
  - 11-22 04:16 이후: 조절기 Wi-Fi 설정에 NAS 주소를 직접 넣음(자체 프로비저닝, 6절)
- 수집 서버는 모든 송수신 원본, 명령, 조작 메모(marker)를 회차 폴더에 남깁니다. 회차 이름은 `field-날짜-번호`입니다.
- `field-20261120-*` 폴더는 실제로는 **11-21 저녁**에 실행했습니다. 설정 파일의 날짜를 바꾸지 않아 이름만 20일로 붙었습니다.
- 수집 서버가 한 번에 연결 하나만 받던 시기(11-21 23시 이전)에는 조절기가 재접속할 때 새 연결이 거부되어 자료가 빠진 회차가 있습니다.

## 5. 주제별 결론

### 5.1 ACK

- 조절기는 ACK를 받지 못한 이벤트를 3~5초마다 다시 보내고, 그동안 다음 이벤트를 보내지 않습니다. 반복 중 본문은 최신 값으로 바뀝니다(01, 02, 11 회차).
- 서버는 모든 장치 이벤트에 ACK해야 합니다.

### 5.2 원격 명령

| 명령 | ID | 실물 확인 회차 |
|---|---|---|
| 실내 희망온도 | `0102` | 21 |
| 전원 OFF/ON | `0101` | 21 (ON은 모드 보고로 응답) |
| 온돌 온도 | `0104` | 20, 21 외 다수 |
| 온수 온도 | `0115` | 21, 27 |
| 목욕 | `0105` | 21 |
| 외출 | `0106` | 21 |
| 온수 전용 | `0114` | 22 |
| 난방 예약 | `0108` | 22 |
| 난방수 온도 | `0103` | 27 |
| 24시간 예약 | `0107` | 27 |

- ACK는 보통 0.5~0.7초 안에 옵니다. 1.9초까지 걸린 적이 있습니다(27, 33 회차).
- 33 회차 16:37:41의 온돌 명령은 10초 안에 ACK가 없었습니다. 재개된 세션 직후였습니다.
- 실내 온도와 예약 외의 명령은 ACK만 오고 바뀐 값을 보고하지 않습니다. 다음 `01FF`의 저장값으로 확인합니다.

### 5.3 연결과 재접속

- 서버가 다시 시작되면 조절기는 다음 셋 중 하나로 다시 붙습니다.
  - `0001`부터 새로 시작
  - `0001` 없이 `01FF`부터 보냄(재개된 세션, 24·33 회차)
  - 연결만 맺고 아무것도 보내지 않음(보통 약 130초 뒤 Wi-Fi 재연결, 한 번은 7분 넘게)
- 조절기는 Wi-Fi를 다시 붙을 때 예전 TCP 연결을 닫지 않고 새 연결을 엽니다. 서버는 새 연결을 받고 예전 세션을 버려야 합니다.
- `01FF`는 약 301초마다 오고, 접속 직후에도 한 번 옵니다.
- 연결이 끊기면 조절기는 약 15초마다 DHCP를 다시 시도하고, IP를 받으면 `0001`부터 새로 시작합니다(3.5절, 4시간 20분 동안 계속 시도).
- Windows 모바일 핫스팟은 상위 네트워크가 바뀐 뒤 DHCP에 응답하지 않을 수 있습니다(3.5절 05:10~09:31). 핫스팟을 껐다 켜면 풀렸습니다. 핫스팟을 쓰는 시험에만 해당합니다.

### 5.4 `0003` 연결 확인

- 접속(`0001`) 약 60분 7~8초 뒤부터 같은 주기로 옵니다. 이벤트나 명령은 시작 시각을 바꾸지 않습니다.
- 제조사 서버는 `0003 000b <token> <YYMMDDhhmmss> <밀리초 2B>`로 바로 응답하고, 그러면 반복 없이 한 번으로 끝납니다(3.5절).
- 수집 서버가 보낸 응답(응답 없음, 빈 `0003`, 길이 10의 시간 응답, 6바이트 시간, `0001` 시간 응답)에는 10초 간격으로 반복했습니다. 반복은 조절기 이벤트나 서버 명령에 ACK가 오가면 멈췄습니다.
- 그래서 반복을 멈추는 것은 길이 필드 11의 시간 응답으로 추정합니다. 이 프레임을 로컬 서버에서 보낸 시험은 아직 없습니다.
- 반복 중에도 연결과 상태 보고는 정상입니다(30 회차 6.7시간). 해가 없습니다.

### 5.5 자체 프로비저닝 (11-22 03:29~04:16)

| 시각 | 시도 | 결과 |
|---|---|---|
| 03:29 | 줄 구분 CR, 암호 오타 | 조절기가 받아들이고 재시작했지만 Wi-Fi에 붙지 못함 |
| 03:37, 03:40 | 줄 구분 LF | 무시됨 |
| 03:48 | 제조사 앱의 실제 바이트 캡처 | 줄 구분이 CR임을 확인 |
| ~04:16 | 서버 주소에 IP, `IP.nip.io`, `nas.IP.nip.io` | 조절기는 주소를 항상 DNS로 묻고, 첫 마디 3글자 뒤에 `4`를 끼움. `nas.<IP>.nip.io`(조회 이름 `nas4.<IP>.nip.io`)로 **성공** |

- 이 방식으로 로컬 DNS를 바꾸지 않고 조절기가 NAS로 바로 붙습니다.
- 부팅 때 `igis` HTTP 조회와 nip.io 이름 풀이에 인터넷이 필요합니다.

### 5.6 이 조절기에 없는 기능

- 절약 모드, 온수 학습: 버튼을 눌러도 아이콘이나 메시지가 없음
- 즉시 상태 요청: 32 회차
- 난방 예약 순서(가동 먼저/정지 먼저)의 원격 변경: 명령에 순서 정보가 없음
- 가스 사용량 원격 조회: 조절기 화면 안에서만 동작
